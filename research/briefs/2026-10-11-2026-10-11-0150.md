# Brief: 2026-10-11, run 0150: does a learned subtree library beat restarted tree GP?

**What was tested and why.** Run 0024 made restarted tree GP (R-tree) the bar. Its cost was about 90k evaluations
per DG search, and it solved 99.6%. A8's learned tape bias no longer beat it in evaluations. Strategy 0150
asked whether learning can improve an already strong structural search.

We built 24 independent libraries, each from 32 new tree-GP searches on the four DG source cells. A library
holds small subtrees (3–9 nodes, containing an input) that recur in at least two source cells, up to 16 of
them. We then ran fresh restarted tree GP on the eight DG target cells in three arms:
- R-tree, unchanged;
- R-lib, which draws half of its mutation donors from the library;
- R-size, which uses random valid donors matched to each library entry's node count and compiled length.

Each arm had 1,536 jobs. Commit `d7ec100`; queue 66 min (prepare 14, scoring 52); all gates passed.

**What happened** (mean evaluations to an exact solution, failures charged at 524k, 95% intervals over the 24
acquisitions):
- **R-lib ÷ R-tree 0.39 [0.33, 0.46]**: about 2.6× cheaper (87k → 34k). R-lib solved 1,536/1,536, against
  1,524 for R-tree.
- **R-lib ÷ R-size 0.41 [0.33, 0.53].** R-size ÷ R-tree was 0.94 [0.79, 1.12], unresolved.
- R-lib was cheaper in all 24 acquisitions (one only barely, at 0.98) and in all 8 cells. On the cell that
  shares the learned predicate it cost 0.12× as much; on the others 0.35–0.53×, including cells whose pair
  split no library predicate contains.
- The gain shows up as more first-attempt solves (1,121 vs 715). Library entries rarely appear verbatim in
  the final solvers.
- Worker seconds agree: 0.37×. With acquisition charged (2.9M evaluations per library), the library repays
  after about 54 [45, 65] target searches.

**What we learned.** This is the first learned bias in this tree to beat restarted tree GP in evaluations,
and it beats it by a lot. Random donors of the same size do not reproduce the gain. What carries it is not
known: the `GT(ADD,ADD)` comparison skeleton, the pair sums `ADD(Xi,Xj)`, or simply more inputs in the
donors. Every learned entry contains an input, while about a third of the size controls contain none.

**Failures and uncertainty.**
- DG is development data, and the libraries are nearly identical: 3 of 4 source cells share one pair split.
  A hand-written five-entry library might do as well, so the 54-search repayment is an upper bound on what
  this information costs.
- Library donors entered about 11% of children, not the planned 25%, because 55% of them were too large for
  the 32-token cap.
- The proposal miscounted the covered cells (5/3 instead of 4/4); the plan corrected this before scoring.
- The effect was beyond the proposal's own surprise threshold. The plan-mandated inspection found no
  accounting route that would under-charge R-lib.
- One analysis agent crashed and was retried; it cost no data.
