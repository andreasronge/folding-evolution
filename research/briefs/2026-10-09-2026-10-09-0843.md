# Brief: run 2026-10-09-0843. Do learned program fragments speed search beyond C? (root 10, question 32) — yes on training cells, 1.57×

**What was tested and why.** The fitted context table C is our strongest decoder. Frequency
projections and random recodings of it all failed to match it. But a previous-token table
cannot propose a whole multi-token computation in one edit. This run asked whether short
fragments taken from training solvers can, used as block edits. From each corpus's G4 solvers
we took 3–6-token windows whose tokens all matter (knockout test) and that recur across cells.
The library for each scored cell came only from the other three cells (32 fragments). C's search
stayed as it was. Each non-elite child got one block with probability 0.2, with the tokens after
it kept intact. The arms were:
- F: an intact fragment.
- B: a block drawn from the library's per-position token frequencies, which keeps token supply
  but drops joint content.
- W: a block sampled from C's own chain, a library-free block edit.
- C: no block edits.

**What happened.** The run is complete and valid: 8 192 searches (16 corpora × 4 training cells ×
32 paired seeds), 74 min in the queue, and every replay and edit audit passed. 95% intervals over
corpora:
- **F/C 1.57× [1.42, 1.75]**. All 16 corpora and both families favour F. The result holds at
  1 × cap and on pairs where both arms solved.
- **F/B 1.60× [1.45, 1.77]; F/W 1.23× [1.12, 1.36].**
- W/C 1.28× [1.17, 1.39]. B/C 0.98× [0.93, 1.04], at the same rate and ~2.8 tokens changed
  per edit.
- Solve rates: C 90.6%, F 93.8%, B 90.8%, W 94.1%.
- The gain is uneven across cells (F/C 0.99–2.17×). On one BE cell, F is worse than W.
- Pre-registered rule 1 fired: *earns review of reuse*. I had guessed F/C 1.0–1.15, so this is
  in the "surprising" region.

**What we learned.** On the cells the libraries came from, inserting learned fragments whole is
a large further speed-up on top of C. The gain is not explained by edit size: marginal blocks of
the same size do nothing, and fragments beat C's own chain blocks by 1.23×. Separately, block
editing by itself beats C's point mutation by 1.28×. The likely reason is that a block edit
keeps the rest of the program, while C's mutation re-decodes everything after it, but this is
not yet shown.

acquisition question of whether evolution can harvest fragments itself. About 21 h remain in
the autonomous run.

**Failures and uncertainty.**
- The libraries are mostly the bank's common 3-token pieces (`input first gt`, `input
  reduce_min input`), shared by almost all leave-one-out libraries. Leave-one-cell-out therefore
  guards weakly against memorization, so this is not transfer evidence.
- Solvers under F contain more library fragments, but that is occurrence, not proof that the
  inserted blocks did the work.
- The library was fitted externally, so this says nothing about evolutionary acquisition.
- The smoke run mispredicted per-arm solve counts (W by 135), as the plan warned. The precision
  forecast was accurate.
