# Brief: 2026-10-10, run 2001: which part of a DG-built bias carries its advantage?

**What was tested and why.** In run 1717, A8 builds acquired on the double-gate family (DG) were about 3×
cheaper on unseen DG cells than builds acquired on branch-sum (TS). Each build is a context table plus a
fragment library. To learn what a future learner must acquire, we swapped the two components between the
24 saved DG builds and the 24 saved TS builds. That gives six arms (table/library: D/D, T/T, T/D, D/T, D/∅,
T/∅; ∅ = no block edits), 24 donor pairs, fresh seeds, 8 DG and 8 TS cells, and 4 608 searches. No new
acquisition. Commit `6dabda8`.

**What happened** (DG cells, 2 × cap, 95% intervals):
- The fresh native gap reproduced: 3.03× [2.28, 3.97] (1717: 2.98×).
- Bare tables alone: D table 3.26× [2.43, 4.30] cheaper than the T table, as large as the native gap.
- On the T table, the D library beats no library 3.05× [2.32, 4.07] (24/24 pairs).
- **Primary:** on the T table, the D library beats the T table's own library 1.95× [1.43, 2.66]. That is
  **unresolved** against the 1.5× margin, missed by 0.07 (22/24 pairs > 1). The hybrid stays 1.55× [1.15,
  2.09] behind the native D pair.
- The D library also beats the T library on the D table (1.35× [1.10, 1.68]), so no library was shown to
  need its own table.
- On TS cells the libraries are interchangeable (1.01× [0.83, 1.25]): the D library costs nothing there.
- Queue 89 min; all validity checks passed.

**What we learned.** Both components carry the DG advantage. The DG table shows it with no library at all,
and the DG library is a portable add-on: it helps a foreign table and is free on the other family.
Neither dominates; which looks larger depends on the order of the swaps.
