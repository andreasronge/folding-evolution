# Brief: run 2026-10-09-0306, do the context tables win by token position? (root 10, question 30) — no

**What was tested and why.** The fitted context table C beats K, which is G4 reweighted to C's
*pooled* token frequencies, by 2.48× on then-addition. C and K also differ in which tokens sit at
which tape positions. Two frozen projections of each of the 16 C tables test whether position
explains the gap. **Q** is G4's grammar matched to C's frequency at each of the 32 positions.
**P** is independent per-position draws with no grammar. The result decides whether a learner
should aim at a positional frequency map or must capture dependencies. This is a rerun of 0239
(which stopped 70 s over its runtime price). The only changes are a 3 h 15 min timeout and a
reviewer-corrected admission rule.

**What happened.** The run was complete and clean: 4 096 new searches paired with the old C/T/K
rows, replays bit-exact, 96 min of scoring. 16 corpora, 95% intervals:
- **C/Q 2.41× [2.11, 2.75]** (1 × cap 2.21×, both-solved 1.95×). All 16 corpora and all 16 cells
  are above 1.2. The pre-stated label is *insufficient*.
- **C/P 5.47× [4.79, 6.25]**, also insufficient. P solves 50.5%, against C 86.5%, Q 73.9% and
  K 72.5%.
- **Q/K 1.03× [0.93, 1.13]**: per-position matching gave no resolved gain over pooled matching
  (a gain above about 1.13× is excluded).
- C changes about 3 tokens per mutation, Q and K 1.7, P 0.9.

**What we learned.** Neither pooled nor per-position token frequency, on G4's grammar or alone,
reproduces the fitted table's advantage on this bank. This holds for these two frozen projections
under these operators. The remaining gap sits in C's conditional rows, or in the wider mutation
neighbourhood those rows create; this run cannot separate the two.
