# Brief: run 2026-10-05-1957, does the sum>2 speed-up go through the max>2 shortcut? (09)

**What was tested and why.** In run 1814 the "rest of the vector" arm R reached an exact sum>2
solve 1.61× sooner than uniform while sampling 4× fewer exact solvers. R also meets many more
programs that compute max>2, which fits most sum>2 training sets. Idea (G3): max>2 is a stepping
stone. Test: on training sets where max>2 always fits, bar any exact max>2 program from
reproduction ("veto") and see whether that slows R more than uniform. Four cells (U/R ×
ordinary/veto), a 50-seed pilot, then 600 or 800 seeds only if the pilot showed enough power.
Root 01's last experiment, pre-registered.

**What happened.** The pilot ran cleanly in 4 min (200/200 solved, all re-verified exact, veto
never leaked). Power for one of three criteria (showing "veto costs R little" if true) was
0.48 / 0.53, under the 0.80 gate, so **the main stage did not run**. No registered result.

Pilot only (n = 50, exploratory):

| | U | R |
|---|---|---|
| Runs where exact max>2 appeared | 25/50 | 35/50 |
| …solver's immediate parent was exact max>2 | 21/25 | 34/35 |
| …veto slower / faster / tied | 20 / 1 / 4 | 29 / 5 / 1 |
| Generations first max>2 → solve, ordinary → veto | 1 → 4 | 2 → 10 |
| Veto runs that still solved | 50/50 | 50/50 |

Registered ratios on the pilot, all with intervals touching 1: R's gain on these sets 1.30
(0.71–2.32), veto cost to R 1.46 (0.99–2.08), to U 1.06 (1.00–1.46), interaction 1.38
(0.82–2.00).

**What we learned.** When the exact max>2 program shows up, it is almost always the last step
to the solve, in both arms; blocking it costs a few generations but never the solve, because
near-max programs (≈99% agreement with max>2) take its place. Whether this explains R's
advantage over uniform is still unknown.
