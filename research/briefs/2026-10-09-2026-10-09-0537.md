# Brief: run 2026-10-09-0537. Does C win because its mutations reach further? (root 10, question 31) — no, wider random edits hurt

**What was tested and why.** The fitted context table C is 2.41× faster than Q, which is G4
matched to C's per-position token frequencies. C's mutations also change more tokens: about 3 per
allele resample, against Q's 1.7. This run asked whether that wider edit neighbourhood, rather
than C's content, explains the gap. Each Q table was recoded by shuffling which alleles map to
which token, separately in each (position, previous-token) row. Every row kept its exact token
counts, so the distribution of random programs is exactly Q's, and runs started from identical
programs. Only how far an edit ripples downstream changed. There were two doses: R30 (30% of each
row shuffled, tuned to C's width) and R100 (whole row).

**What happened.** The run is complete and valid: 4 096 searches, 100 min, all replay and
equality gates passed. The queue says `failed`, but that was a missing import in the last plot,
after the results were written. 16 corpora, 95% intervals:
- R30 hit C's width: 3.00 tokens per resample, against C 2.95 and Q 1.71.
- **R30 was 1.17× slower than Q [1.09, 1.25].** In the analysis convention cost_Q/cost_R30 is
  0.855 [0.80, 0.91]. 14 of 16 corpora are below 1, and both recoding realizations and both
  families agree.
- R100 was 2.4× slower than Q and solved 52% of searches, against Q's 74%.
- R30 stays 2.8× slower than C [2.5, 3.2].
- The pre-stated label is *no useful gain at either dose*. This was the expected outcome.

**What we learned.** At a fixed random-program distribution, making edits ripple further at
random costs search speed, and more ripple costs more: locality matters in this representation.
So C's advantage is not its edit width as such. It is C's content, or the particular structured
way its rows couple tokens. This run cannot tell those two apart.
