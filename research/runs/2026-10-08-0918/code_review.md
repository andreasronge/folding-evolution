## What was checked and holds

1. **Arm wiring.** `Modifier.__call__` receives `[elite indices..., first parent of each child]` from `_reproduce_batched`; rows for non-elites are copied from the recipient (the `a` parent whose leader/runs seed the crossover child), perturbed with the modifier's own Generator, clipped to ±3; elite rows are copied unperturbed with depth retained. The returned `(n_children, 22)` matrix feeds `tagged.mutate_batch` whose row count equals `len(children)`; `_draw_ops` validates the shape and simplex. Frozen scoring (`eb.run_one`) never passes a modifier and uses `cfg.op_weights` from the vector, so the frozen phase measures the extracted distribution and nothing else.
2. **Broken control.** Shuffle happens after every census (including gen 0 and the final census) and before elite/recipient selection; `check_acquisitions` enforces `shuffles == 129` per episode for broken and 0 for inherited. The ordering test (`test_broken_permutation_after_evaluation_before_elite_selection`) pins this.
3. **Seeds.** Program seed stream `program/{phase}/{family}/{replicate}` and training streams `cases/{...}/{episode}` omit the arm, so inherited/broken are paired; `modifier/.../{arm}` is per-arm. Phase `timing` vs `main` gives disjoint streams, and `check_acquisitions` rejects any `phase != "main"`, so the four 0843 timing vectors cannot enter. Frozen searches use `MASTER + 100000 + index`, identical across all vectors for a given index and target (shared seeds as planned).
4. **Equal exposure.** Every episode runs exactly 128 reproductions and 129 censuses regardless of solve; verification is skipped after the first exact hit (`(None, 0, 0) if ep["solved"]`), selection continues. Roster and schedule checks reject any deviation before extraction.
5. **Metric.** Cost is `gen*pop + pos + 1` on first exact (full-domain verified) solve, cap 262144 for completed unsolved searches; analysis rejects rows with `complete=False`, `time` outside `(0, CAP]`, or unsolved rows not exactly at the cap, so timed-out searches cannot masquerade as censored ones (critique note 2).
6. **Analysis contract.** `crossed_effects` resamples 20 acquisition indices once per draw and applies them to both learned arms (paired), draws one seed index set per target and reuses it across every vector and contrast; references take a single row. Bootstrap seed is per family. `classify` gives Acquired precedence over Bounded. Family verdicts are never pooled. `linkage_unidentified_by_both_censored`, S lower/upper flags and between-run log SD are emitted as planned.
7. **Roster change (511711c).** `--reference-seeds` only accepts 16; `reference_arms(include_fit)` is threaded through jobs, manifest (`frozen_search_count`, `reference_arms`), roster validation, bootstrap contrasts (`fit_over_inherited` only when present), break-even and plots. Manifest check across stages compares master, source hashes, reference indices/arms, spec hash and search count, so a stage run with `--omit-fit` cannot be mixed with one without.
8. **Queue.** No `parallel_group` on any entry, so the runner executes them sequentially (each entry is its own group); `date_dir` is computed once per runner invocation, so the `$RUN_DIR/../<sibling>` paths resolve. Timeouts 5824/1317/3162/300 match `cost/projection.json` (10603 s ≤ 10800 s). Stage markers are written only after roster/completeness checks pass.
9. **Critique.** Notes 1–5 are reflected in plan.md and in code (repricing, fit fallback, 20 replicates, paired/shared resampling, acquired precedence, missingness ≠ censoring, identification caveats). Notes 6–7 are steward scope-audit items; plan.md and preparation.md correctly defer them and flag them rather than editing digest/questions.

## Minor notes (runtime risk, not validity)

- **Max scoring timeout is priced on old-law learned vectors.** The 2243 learned max cells cost ~10.7 s/search because those vectors never produced training-perfect candidates (0/8 solves, no verifier calls). The new fixed-duration law solved 26/48 max episodes in the timing run, so its frozen searches will likely trigger full-domain verification of many near-solutions; the only verifier-heavy max cell measured (uniform max1) averaged 55 s/search with a 170 s maximum. At even ~25 s/search the 1280 learned max searches exceed the 3162 s timeout on 10 workers. The plan and critique already name this as an unvalidated tail. If max-scoring times out: the acquisition and sum-scoring outputs on disk remain valid (same commit, manifests match), so re-queue only `max-scoring` and `analysis` with a repriced timeout rather than re-running acquisition. Note also that `analyze` requires both families, so a max timeout withholds the sum verdict too until that re-run.
- **Hidden per-job deadlines.** `acquire` defaults to a 1200 s per-acquisition deadline and `score` to 600 s per search; neither is in plan.md. A single job hitting one becomes `complete=False` and fails the whole stage loudly (no partial verdict is possible, which is correct). Margins are 2.8× the slowest measured acquisition (433 s at 4 workers) and 3.5× the slowest measured search (170 s), wider than the plan's 2× stage allowance, so they are unlikely to bind, but they add a failure mode without adding protection beyond the stage timeout. Consider dropping them or setting them to the stage timeout in a future revision.
- **Rayon threads.** `rust_tag_outputs` parallelises over tapes with Rayon's default pool (12 threads here); `inherited_bias.py` does not set `RAYON_NUM_THREADS=1` as `evolve_bias.main` does, so 10 workers run ~120 evaluation threads on 12 cores. Evaluation is ~15% of acquisition time (verification of a single genome is not parallelised), so the effect on the 10-worker projection is modest, but it is part of why 10-worker throughput is "unvalidated". The 0843 timing run had the same configuration at 4 workers, so the measured means already include some of this contention.
- **Core layout.** The host reports 12 physical cores (Apple M6). The projection's work/10 assumption is reasonable here; workers landing on efficiency cores would lengthen the tail within the stage allowances.
- `--workers` is accepted but unused in `analyze` mode; harmless.
- The Price covariance counts elite copies as offspring of their source row; descriptive only, as the plan states.
