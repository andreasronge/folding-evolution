## Minor notes

1. **R-size may be dropped by a gate artifact rather than a real runtime constraint.** Effective concurrency is measured on the 288-job calibration batch, which includes the ramp-down tail of jobs up to about 36 s on an ideal wall of about 160 s. That biases concurrency low (plausibly 8.5–9.5), and the five-arm threshold is 8.9, so dropping R-size is roughly a coin flip even though the true five-arm runtime is about 65 min. This is within the approved ordered fallback and R-size is descriptive, so not blocking. If R-size is absent from the score, the analysis should attribute that to the projection's conservatism, not to runtime.
2. **The score path was not run end to end before handoff** (only the smoke-rejection test). It mirrors 0524's score path, which ran cleanly, and the added checks are deterministic recomputations of prepare-phase outputs, so the risk is a validation mismatch that fails fast before any search, not a wrong result.
3. **The `then` subgroup check** (`len(then) == 4`) is a hard assertion inside `summarize()`; it holds for the frozen bank (the reporting test uses the real bank snapshot), but if it ever failed it would abort reporting after scoring. Raw rows would still be in `search.jsonl`.
