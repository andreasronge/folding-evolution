## Minor notes

1. **Timeout headroom for the protected phase is adequate but not generous.** Ordinary work projects to ~9 min; at a 10 % capped fraction the slowest arm adds ~36 min, total ~45 of 59.5 min. At roughly 15 % capped jobs the phase would time out and, by design, yield no inference at all (no partial-grid verdict). All evidence (stage 0: 12/12 first attempt; smoke: 48/48 solves, 0 capped) says the real capped fraction will be far below 10 %, so I do not consider this blocking. If it does time out, the analysis should say so rather than salvage partial rows.
2. **`seed_audit` is fragile to unrelated files.** It rglobs the main checkout's `experiments/output` for any `*schedule*`, `*seed_audit*` or `*historical_seeds*` JSON not containing the task id and includes paths and SHA-256s in the frozen audit. Any new such file written by another process before the protected phase would make `load_bank` fail closed in every phase. The queue's own outputs are excluded by task id, and nothing else is scheduled, so this is a robustness note, not a correctness issue.
3. The smoke development interval (R-all/R-tree 0.36 [0.15, 1.30]) comes from one build and six cells; the build bootstrap is degenerate there. It is correctly labelled descriptive and selects nothing.
4. The economics block's `projected_*_jobs_seconds` in `throughput()` extrapolates from the batch it was computed on; the four-job cap-timing fixture's projection is meaningless and should not be quoted in analysis. Per-job worker seconds (31–35 s capped) are the usable numbers.
