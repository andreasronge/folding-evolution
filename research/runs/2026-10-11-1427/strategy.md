**What the program has learned.**

- **Map bias matters, but random sampling does not explain every evolutionary
  result.** Random-program frequency predicts easy behaviours better than hard
  discovery. Cheap joins explained the tested composition advantage; lineage
  mixing obstructed establishment of rare shared forms. These are scoped
  representation/operator effects, not general superiority of folding
  ([01](../../questions/01-map-bias/question.md)).
- **Programs found by evolution teach reusable bias when fitted externally.**
  Context fitted to exact solvers beat token-only fitting, including about
  **2.1×** on then-addition's fresh shape. Pooled/positional frequency replacement
  and random mutation widening did not reproduce that advantage. Fragment
  edits added speed; cheap feedback acquisition retained useful transfer.
  DG-acquired bias was about **3×** cheaper than TS-acquired bias on DG; the
  reverse preference remained unresolved. Both tables and libraries carried
  useful information. Outer selection learned token weights, but the tested
  context extensions added no resolved gain
  ([10](../../questions/10-compositional-map-transfer/question.md)).
- **Stronger baselines narrowed the practical claim.** Matched restarts let
  ordinary tree GP use about a fifth fewer DG evaluations than A8, although A8
  remained cheaper in worker seconds. Tree-source libraries subsequently reduced
  evaluations to **0.39×** on DG and **0.25×** on one fresh gate-sum shape.
  Learned arrangement mattered where the learned predicate matched; a supplied
  sum prior beat acquired TS libraries on the other splits. Acquisition did
  not repay against that prior through 200 searches. Libraries also harmed
  easy native targets ([44](../2026-10-11-0024/analysis.md),
  [46](../2026-10-11-0348/analysis.md),
  [51](../2026-10-11-1019/analysis.md),
  [49](../2026-10-11-0833/analysis.md)).
- **Useful acquisition extends beyond small sums, at development scope.**
  Uncapped semantic libraries reduced order-task cost to **0.40 [0.32, 0.50]**
  of R-tree, across 24 acquisitions and six development cells; acquisition
  repaid after about five searches. The supplied order prior remained **7.3×**
  cheaper. Removing the cap changed size, content and draw probabilities
  together; the helpers' causal share is unresolved
  ([1228](../2026-10-11-1228/analysis.md)).
- **The latest probe supplies a boundary observation, not a portability verdict.**
  On rectified-sum sources, 384/384 searches solved, but only 34 solvers contained
  their own helper and nine contained an emittable one; none survived both
  recurrence and size requirements. R-all cost **1.03 [0.96, 1.10]** of R-tree.
  Supplied rectifiers helped (**0.57×**, 73/96 solves versus 20/96), but missed
  the probe's investment threshold. Many target runs capped. This supports
  ending this source design; it establishes neither impossibility of acquiring
  rectifiers nor absence of useful headroom. Protected cells were untouched
  ([1315](../2026-10-11-1315/analysis.md)).
- **Useful inherited learning remains unshown.** Root 23's inherited token law
  did not improve frozen fresh search over uniform on its training tasks; the
  scaffold was much better. Linkage helped versus shuffled ancestry on max
  without establishing usefulness. That limits one procedure, not inheritance
  generally ([23](../../questions/23-heritable-variation-bias/question.md)).

**Which roots matter now.** New **55** has the highest immediate value: can a
variation law known to improve population search earn a reproductive advantage
for its carriers? This is a different question from whether we can extract
more content. Existing **10** remains the strongest evidence for the README's
cheap-reuse goal, but another source/extractor change would leave the inheritance
gap intact. **23** remains the long-term frequency-learning question; its old
reopening conditions are not met and it stays parked. Root 55 isolates selection
among structured alternatives, without rerunning its continuous token learner.
**01** informs the linkage risk, but another threshold, rarity ladder or shared-
helper census would not decide this next learning mechanism. Folding, CA and
runtime plasticity address other gaps; broad PSB2 work needs an adapted interface
and a priced family split, and would combine too many new uncertainties here.

The distinction worth paying for now is **population benefit versus carrier
benefit**. Root 01 warns that mixing can separate them; root 23 never established
a useful frozen law. Root 10 now supplies one. Even a well-bounded negative in
this easier standing-variation assay would argue against immediately building
an inherited content-discovery engine. A positive would supply the missing
selection calibration, while leaving content discovery and practical superiority
to fixed R-all unresolved. That decision warrants the complete 10–14 h cost.

**What the steward should work on next.** *When useful structured variation is
already available, can program selection propagate an inherited choice to use
it, and does that choice remain useful after programs are reset?* Follow the
[new plan](../../plans/inherited-library-choice.md). Use saved independent order
libraries and existing development cells. First measure the selectable signal,
linkage dependence, initial-mixture headroom and frozen readout. More inherited
allele movement alone is not a useful answer. This is a mechanism test on
development data, not new-family transfer or evolved library content.

I decline protected order scoring (**4–5 h**) this block: it tests new combinations
of the same helpers without changing the acquisition mechanism. Helper ablation
(**2–3 h**) would explain the R-all package but is unnecessary to ask whether
that already useful package can be selected. A gate-sum return or deployment
gate (**4–6 h**) would refine use policy before we have chosen to deploy it.
Reconsider these when a transfer, ingredient or mixed-difficulty deployment
decision specifically needs them. Keep question 50 parked.
